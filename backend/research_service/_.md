# backend/research_service/ — the extension-owned Python package

Read-only over the frozen baseline (`extensions/README.md`); implements
`extensions/plans/CONTRACTS.md` C1 (ownership, identifiers, data) and C2 (partition, export,
snapshot). Never patches a baseline file, never imports a private baseline symbol to bypass a
public contract, never writes into a baseline-owned path.

| File | Purpose |
|---|---|
| `adapter.py` | `read_measurements(model_ids, gene_ids, layers)`, `read_model_metadata(model_ids)` — bounded, Parquet-predicate-pushkown-first / chunked-CSV-fallback reads of `data/processed/` (mirrors `scoring/score.py::_load_filtered`'s V6-10 strategy, reimplemented rather than imported since that function is private). Raises on an unknown layer, a missing table, or a duplicate `(ModelID, ensembl_id)` key in a single-row-grain layer; never silently returns empty. |
| `serialization.py` | `to_json_safe` (re-exports `scoring/export.py`'s public `sanitize_for_json`), `canonical_bytes`, `content_hash` — the strict, deterministic JSON layer snapshot IDs are computed from. |
| `snapshot.py` | `create_snapshot(native_result, manifest, model_metadata)`, `save_snapshot(snapshot)`, `load_snapshot(query_id)`, `compute_query_id(native_result, manifest)` — the immutable `research-query-v1` snapshot object every later extension stage (S04–S09) reads from. `native_result` is deep-copied once at creation; `context`/`alternatives` are left `None` for later stages to populate beside it, never inside it. |
| `reactome_membership.py` | Read-only, human-only Reactome pathway-membership fallback for when the built graph is unavailable. It detects unpulled Git LFS pointer stubs explicitly and caches only under `backend/research_service/runtime/`. It never imports or runs the frozen graph builder. |

Membership is never represented as activation, enrichment, causality, or cell-line sensitivity. |

Its fixed reference cohort is independent of native top-k/eligibility; its candidate universe remains restricted to native positive eligible top-N plus tail. It never calculates or changes a suitability score. |
| `alternatives.py` | `find_alternatives(snapshot, anchor_id, profiles, policy)` — pure C5 query-profile similarity aggregation over S06 percentiles. It returns at most three same-lineage, native-eligible candidates with per-view coverage and leave-one-view-out sensitivity; it preserves native D/tier and never rescales, replaces, or interprets them. |
| `compare.py` | `compare_models(snapshot, model_ids)` — fixed-order, read-only C6 comparison for exactly two or three same-snapshot native records. It retains Low/veto evidence, model-selection order, units/states/provenance, and `not_computed` component status; it never rescales or chooses a winner. |

| `service.py` | `ResearchService` — the S09 local orchestration boundary. It accepts a completed native export only from the opt-in ranking callback, creates a trusted snapshot, lazily attaches context/alternatives, serves a two/three-model comparison/export, retains BR07's explicit persistent route evaluation, and AUTO03's fixed-plan one-task advance. AUTO04's frontend submits no route selection and repeatedly calls only the bounded advance endpoint while its current query remains active. |
| `api.py` | Opt-in `/research` FastAPI router: trusted-ID context, alternatives, comparison, complete export, BR07 manual routes, and AUTO03 automatic-state/one-task-advance endpoints. No endpoint accepts client-provided native evidence or a path. |
| `evaluation_queries.json`, `evaluate.py` | S13's frozen seven-case query battery and read-only evaluation summariser. It records runtime, partitions, layer/context coverage, alternatives availability and fixed sensitivity/invariance checks from already-run artifacts; it never invokes/tunes the scorer. |
| `routes/contracts.py` | BR01's immutable route-family, context, source-role, relationship and long-evidence-ledger contracts. It only validates declarations and deterministic IDs; it does not read data, evaluate a route or alter native results. |
| `routes/registry.py`, `route_policies/` | BR01's strict loaders for the fixed method registry, frozen controls and validation-only source policy. Only registered `route_input` sources can be returned to later route engines; validation-only sources are rejected. |
| `route_policies/automatic_route_policy.json`, `routes/automatic_plan.py` | AUTO01's versioned, fail-closed automatic-background policy and AUTO02's pure planner. The planner reads only the saved canonical query, deduplicates/sorts canonical inclusion IDs, creates the fixed six-task battery for each of the first ten lexicographic pairs, retains an omitted-pair ledger and policy digest, and leaves serializable pending state for AUTO03. It cannot read native results, candidates, route outcomes or source data. |
| `routes/evidence_adapter.py` | BR02's read-only `adapt_route_evidence(...)` projection. It exact-resolves frozen gene-reference entries, uses the complete immutable snapshot partition, preserves row-order-independent event multiplicity/raw values and actual cohort denominators in the long ledger, joins coverage/lineage/per-gene common-essential context, and caches only under `backend/research_service/runtime/routes/`. It does not evaluate a route or alter native output. |
| `routes/conditional_dependency.py` | BR04/BR05's immutable-BR02 conditional-dependency evaluator. It preserves the accepted directional mutation path and adds source-RNA Q80 versus Q20 context independently per lineage, with explicit thresholds/non-discriminating exclusions, raw and lineage-median-adjusted target Chronos, locked bootstrap/holdout uncertainty, assay/QC uncertainty and model packets. It never rereads native data or changes native ranking. |
| `routes/codependency.py` | BR06's immutable-BR02 CRISPR codependency evaluator. It calculates raw and lineage-median-adjusted signed Spearman association on shared finite Chronos rows, with lineage-stratified bootstrap, conservative holdouts, separate two-gene common-essential safeguards and joint descriptive model states. It remains exploratory functional association evidence and never changes native ranking. |
| `routes/router.py`, `routes/serialization.py` | BR07's declared-only dispatch and deterministic snapshot attachment envelope. The map is keyed by BR01 relationship ID/policy version, preserves the first stored orientation for symmetric requests and contains no timestamps or inferred route choice. |
| `routes/validation.py` | BR09's downstream validation-only runner. Its preserved preregistration manifest froze controls/registry/validation sources/snapshot/seed/grid before first outcomes; its chained final manifest freezes current hashes and governed identities before the clean final rerun. It executes only registered controls, writes deterministic evaluation exports, distinguishes model-only from policy-status sensitivity, and inventories Sanger/PRISM/fusion corroboration without ever feeding those sources to a route engine. |

Outputs land under `backend/research_service/runtime/snapshots/` (gitignored, `backend/research_service/.gitignore`) —
generated, per-machine, rebuildable from the same query against the same baseline. Test fixtures
use `backend/research_service/runtime/test-temp/`, never a system temp directory.

## Snapshot ID

SHA-256 over `{native_result, manifest}` (canonical JSON: sorted keys, `allow_nan=False`), with
any timestamp-shaped key stripped from `manifest` first. The query itself is not a separate
input — it's read from `native_result["query"]`, since `scoring/export.py::export_query_result`
already carries `inclusion_genes`/`exclusion_genes`/`filters` there (S02). Same query, same data,
same method → same ID, regardless of when it ran or what order a dict's keys happen to be in.
Any change to the query, the data, or the scoring method changes `native_result` and therefore
the ID.
